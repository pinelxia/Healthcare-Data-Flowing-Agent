# PRD：跨境合规评估智能体

## 1. 背景

香港居民在内地就医后向香港保险申请理赔，香港保险需通过跨境数据空间向内地医院订阅就诊摘要、费用明细与理赔证明。本组件是订阅审批链路中的**合规评估环节**：对每一笔订阅申请，从合规知识库检索相关规则，结合结构化策略给出 `allow / manual_review / deny` 判定。

## 2. 目标与非目标

**目标**
- 对订阅申请输出三态判定：`allow`（满足条件，可继续交付）、`manual_review`（信息不足或风险较高，需人工审批）、`deny`（违反策略或缺少必要条件，禁止交付）。
- **判定确定性**：判定只由结构化策略引擎产生；LLM 仅辅助检索、归纳、解释，不能绕过确定性规则直接放行。
- **全程可审计**：每次判定返回命中规则、使用证据、缺失信息、策略版本。

**非目标**
- 不提供正式法律意见；不连接真实医院/保险系统；不处理真实个人数据（全部 Mock，见 [assumptions.md](assumptions.md)）。
- 本期不做可信数据空间的审批流（仅智能体本身，接口预留）。

## 3. 用户与场景

| 角色 | 场景 |
|------|------|
| 可信数据空间审批服务 | 收到订阅申请 → 调用本组件评估 → 按判定放行/驳回/转人工 |
| 合规审计人员 | 查询判定报告，核对命中规则、证据与策略版本 |
| 开发/演示 | CLI 与 Mock 样例跑通三条判定路径 |

## 4. 输入输出契约

**输入：订阅申请 `SubscriptionApplication`**
- 申请方：角色、机构 ID、所在区域
- 用途：用途编码 + 用途描述（自由文本，供检索）
- 数据：数据类型（就诊摘要/费用明细/理赔证明）、具体字段清单
- 交付：目的地连接器、接收方
- 合规属性：保存期限、订阅有效期、证据材料（身份证明、患者授权、理赔订单号等）
- 期望策略版本（可选，缺省取最新）

**输出：判定报告 `VerdictReport`**
- `verdict`: allow / manual_review / deny
- `policy_id` + `policy_version`（实际使用的策略版本）
- `matched_rules`：命中的规则（规则 ID、名称、状态、理由、条款引用、来源、风险等级）
- `evidence_used`：本次判定使用的证据
- `missing_information`：缺失的信息（引擎判定，权威）
- `explanation`：模型辅助生成的归纳解释（**仅供参考**，不构成判定依据）

## 5. 三态判定定义

| 判定 | 定义 | 典型触发 |
|------|------|---------|
| allow | 全部适用规则通过，无缺失必要条件 | 身份/用途/字段/目的地/期限/证据全部合规 |
| manual_review | 信息不足或风险较高 | 缺失必要证据材料（可补交）；命中高风险组合规则 |
| deny | 违反策略或缺少必要条件 | 用途不在允许列表；字段超出最小化白名单；身份未登记；缺身份证明 |

判定优先级：**deny > manual_review > allow**（fail-closed：无任何规则命中时判 manual_review）。

## 6. 验收标准

1. 三个 Mock 样例分别稳定产出 allow / manual_review / deny，且报告包含全部四要素（命中规则、证据、缺失信息、策略版本）。
2. LLM 无法改变判定：即使模型输出包含"建议放行"，报告 verdict 仍由引擎决定（有专门测试锁定）。
3. LLM 不可用时（无 API Key / 超时 / 返回异常）自动降级为本地检索 + 模板解释，判定流程不受影响。
4. 单测 + 集成 + CLI 端到端覆盖三条路径，行覆盖率 ≥ 80%。
5. 提供 FastAPI 接口（`POST /v1/assess` 等）与 CLI（`compliance-agent assess`）。
